**یک برنامه‌ی دسکتاپ بومی ویندوز برای پیکربندی سوییچ و روتر سیسکو — بدون نیاز به حفظ کردن حتی یک دستور.**

از طریق **SSH** یا **Serial (پورت COM)** وصل شو، و به‌جای تایپ دستورهای خام IOS از حفظ، با کلیک روی دکمه‌ها دستگاهت رو پیکربندی کن. هر دکمه یه دستور واقعی روی یه session زنده و واقعی می‌فرسته — هیچ‌چیز شبیه‌سازی‌شده نیست.

## چرا این برنامه ساخته شد

این ایده وقتی به ذهنم رسید که داشتم یه سوییچ Catalyst 2960-X رو راه‌اندازی می‌کردم — می‌خواستم یه راه سریع‌تر برای انجام کارهای پیکربندی تکراری داشته باشم، بدون اینکه هر بار همون دستورهای IOS رو دوباره تایپ کنم (یا دوباره سرچ کنم). داستان کاملش رو توی همون پنجره‌ی **About** داخل برنامه بخون.

## قابلیت‌ها

### اتصال
- **SSH** و **Serial/پورت COM** (با `pyserial`)، در یک رابط کاربری. اتصال SSH با اجرای همون کلاینت استاندارد `ssh` خودِ ویندوز (OpenSSH) به‌عنوان یه subprocess انجام می‌شه و ورودی/خروجیش مستقیم به ترمینال برنامه وصل می‌شه؛ یعنی مراحل لاگین (تأیید host key، یوزرنیم، پسورد) دقیقاً مثل تایپ کردن توی یه پنجره‌ی ترمینال معمولی، به‌صورت تعاملی انجام می‌شه.
- ورودی/خروجی ترمینال زنده — می‌تونی مستقیم تایپ کنی یا روی دکمه‌ها کلیک کنی.
- دکمه‌ی **Enter Switch** برای بیدار کردن ایمن یه session که روی پیام‌های بوت/لاگ گیر کرده.

### ۲۳ تب پیکربندی و ابزار کاربردی
هر تب بر اساس سینتکس واقعی Cisco IOS ساخته شده و ترتیبشون از مبتدی به پیشرفته‌ست: اول راه‌اندازی روز صفر، بعد پایه‌های لایه‌ی دو (L2)، امنیت و پروتکل‌های L2، دسترسی از راه دور و AAA، کشف و مانیتورینگ، ابزارهای عملیاتی، و در آخر ابزارهای شخصی‌سازی‌شده‌ی کاربر. جدول کامل و تب‌به‌تب رو در بخش [مرور سریع تب‌ها](#مرور-سریع-تب‌ها) پایین‌تر ببین.

یه نوار **Useful Commands** (Enable، Configure Terminal، End، Yes، No، Exit، Write) همیشه بالای هر تب دیده می‌شه. هر ردیف یا یه **دستور ثابت** (یه کلیک، یه دستور) یا یه **دستور متغیر** (یه فیلد رو پر کن — هاست‌نیم، شماره‌ی VLAN، IP و... — بعد Apply بزن) هست. هر تب هم یه نشان **❓** داره که با یه tooltip دوزبانه (انگلیسی/فارسی) توضیح می‌ده اون تب برای چیه.

### اعتبارسنجی ورودی‌ها
آدرس‌های IP/ساب‌نت/گیت‌وی، هاست‌های RADIUS/TACACS/NTP/Syslog، آدرس‌های MAC، شماره‌ی اینترفیس‌ها، و هاست‌نیم‌ها حین تایپ اعتبارسنجی می‌شن. مقدار نادرست با کادر قرمز مشخص می‌شه و دکمه‌ی Apply/Pin از فرستادنش خودداری می‌کنه — یعنی یه اشتباه تایپی هیچ‌وقت به CLI یه دستگاه زنده نمی‌رسه.

### Pin Commands
- با یه کلیک، هر دستوری از هرجای برنامه رو پین کن (یه دکمه‌ی میان‌بر همیشه دیده‌شونده هم توی هدر برنامه براش هست) — یه لیست شخصی از دستورهای پرکاربردت بساز.
- دستور دلخواه خودتو هم مستقیم اضافه کن، یا هرچی لازم نداری رو حذف کن.
- لیست پین‌شده‌ت رو به یه فایل خروجی بگیر یا ازش وارد کن؛ خودش هم بین اجراهای مختلف برنامه، به‌صورت خودکار ذخیره می‌مونه.

### Switch Models
- یه دکمه‌ی **📋 Switch Models** درست بغل Pin Commands توی هدر برنامه قرار داره.
- با یه کلیک، یه فایل اکسل شامل مدل‌ها/مشخصات/چرخه‌ی عمر سوییچ‌های سیسکو، همراه با برنامه، با هر برنامه‌ای که روی سیستمت برای فایل‌های `.xlsx` تنظیم شده (معمولاً Excel) باز می‌شه — فقط همون فایل، بدون هیچ‌چیز اضافه‌ی دیگه.

### Import / Export
- کانفیگ running یا startup سوییچ رو مستقیم به یه فایل محلی خروجی بگیر (paging رو خودش مدیریت می‌کنه).
- یه فایل کانفیگ ذخیره‌شده رو وارد کن: خط‌به‌خط توی حالت global configuration وارد سوییچ می‌شه، و کامنت‌ها و متن‌های اضافه‌ی خروجی show run رو خودش رد می‌کنه. قبلش هم یه بکاپ ایمنی از وضعیت *فعلی* دستگاه گرفته می‌شه.

### Backup / Diff، به‌صورت پیش‌فرض امن‌تر
- گرفتن snapshot تایم‌استمپ‌دار از کانفیگ running با یه کلیک، ذخیره‌ی خودکار — بدون هیچ پنجره‌ی save.
- **WRITE MEMORY** و **COPY RUNNING-CONFIG STARTUP-CONFIG** (توی تب Save & Verify) به‌صورت خودکار درست قبل از commit یه بکاپ می‌گیرن — بدون نیاز به کلیک اضافه.
- diff یکپارچه بین هر دو بکاپ ذخیره‌شده، تا دقیقاً ببینی قبل و بعد یه پنجره‌ی نگهداری چی تغییر کرده.
- دکمه‌ی **Restore** روی هر بکاپ ذخیره‌شده، با یه کلیک اون کانفیگ رو دوباره روی دستگاه پیاده می‌کنه — بعد از اینکه اول یه بکاپ ایمنی تازه از وضعیت فعلی دستگاه بگیره، تا خود Restore هم قابل برگشت باشه.

### Black Box — دفترچه‌ی رمزنگاری‌شده‌ی اطلاعات ورود
- یه جای خصوصی و محافظت‌شده با پسورد برای ذخیره‌ی هاست‌نیم، یوزرنیم، سکرت و enable secret هر سوییچ (به همراه توضیح دلخواه).
- بار اول ازت یه یوزرنیم/پسورد می‌خواد؛ هر مورد ذخیره‌شده روی دیسک با یه کلید مشتق‌شده از اون پسورد رمزنگاری می‌شه (هیچ‌چیز هیچ‌وقت به‌صورت متن ساده ذخیره نمی‌شه).
- اکانت‌های ذخیره‌شده‌ت رو با یه پسورد جداگانه به‌عنوان فایل خروجی بگیر یا وارد کن.

### Macros
- توالی‌های دستوری دلخواه خودت رو ذخیره کن و با یه کلیک دوباره اجراشون کن.
- Macroهای ذخیره‌شده بین اجراهای مختلف برنامه هم باقی می‌مونن.

### بقیه‌ی امکانات
- **سرچ در تمام تب‌ها** — یه کادر سرچ، دستورهای مطابق رو از **همه‌ی** تب‌ها همزمان پیدا می‌کنه، گروه‌بندی‌شده بر اساس بخش، نه فقط تبی که همون لحظه بازه.
- تنظیم سایز متن خروجی دستورها.
- یه پنجره‌ی About درست‌وحسابی و یه اسپلش‌اسکرین موقع اجرا با آیکون و ورژن برنامه.
- استفاده از فونت Roboto (گوگل) در سراسر رابط کاربری — کادر خروجی/ترمینال عمداً فونت Monospace خودش رو حفظ می‌کنه، تا ستون‌های خروجی CLI هم‌تراز بمونن.

ترتیب و توضیح دقیق جدول زیر، دقیقاً همون چیزیه که توی tooltip های ❓ داخل برنامه هست، تب‌به‌تب از چپ به راست:

|---|---|---|
| ۱ | **Basic** | راه‌اندازی پایه‌ی دستگاه: هاست‌نیم، بنر، enable secret و سایر دستورات اصلی پیکربندی سوییچ. |

| ۱۷ | **Import / Export** | درون‌ریزی یا برون‌ریزی فایل‌های پیکربندی و تنظیمات برنامه. |

| ۲۲ | **📌 Pin Commands** | ذخیره‌ی دستورهای پرکاربردت به‌صورت پین، برای دسترسی با یه کلیک. |

## پیش‌نیازها

- **ویندوز ۱۰ به بالا.** برنامه برای ویندوز ساخته و پکیج شده.
- **Python 3.10 یا بالاتر** برای حالت توسعه — از [python.org](https://www.python.org/) نصب کن (موقع نصب تیک "Add python.exe to PATH" رو بزن). برای اجرای یه exe از قبل ساخته‌شده لازم نیست.
- **یه کلاینت SSH برای اتصال‌های SSH.** برنامه از دستور استاندارد `ssh` استفاده می‌کنه — یا یه نسخه‌ی همراهِ خودِ برنامه، یا OpenSSH Client خودِ ویندوز. اگه هیچ‌کدوم پیدا نشه، یه‌بار از مسیر **Settings ← Apps ← Optional Features ← Add a feature ← OpenSSH Client** فعالش کن. اتصال Serial اصلاً به این نیازی نداره.

## ساخت فایل exe مستقل

روی سیستمی که exe رو بهش می‌دی، نیازی به نصب پایتون نیست — همه‌چیز داخلش هست. چند تا گزینه برای بیلد گرفتن هست، بسته به اینکه چی برات مهم‌تره:

| اسکریپت | نتیجه | مناسب برای |
|---|---|---|
| `setup_and_build.bat` / `build_exe.bat` | یه فایل `.exe` تکی (`--onefile`) | سادگی — فقط یه فایل برای به‌اشتراک‌گذاری |
| `setup_and_build_onedir.bat` / `build_exe_onedir.bat` | یه پوشه (`--onedir`)، با فایل‌های پشتیبان مخفی و قفل‌شده در برابر فضولی تصادفی | استارت‌آپ خیلی سریع‌تر از onefile |
| `build_exe_onedir_compiled.bat` | یه پوشه، ولی به کد ماشین واقعی با [Nuitka](https://nuitka.net/) کامپایل شده، نه بایت‌کد پایتون بسته‌بندی‌شده | قوی‌ترین محافظت در برابر دستکاری تصادفی؛ کاملاً آفلاین بعد از یک‌بار راه‌اندازی کامپایلر C توسط Nuitka |

اسکریپت‌های `setup_and_build*` یه محیط مجازی می‌سازن و همه‌چیز رو از صفر نصب می‌کنن؛ اسکریپت‌های `build_exe*` فرض می‌کنن از قبل یه محیط مجازی فعال داری. هر اسکریپت در پایان کارش، مراحل بعدی و نکات مهم خودش رو چاپ می‌کنه — حتماً یادداشت‌های روی صفحه رو بخون، مخصوصاً برای بیلد با Nuitka.

هر اسکریپت بیلد، کل پوشه‌ی `assets/` رو همون‌طور که هست بسته‌بندی می‌کنه؛ یعنی آیکون برنامه، لوگو، اسپلش‌اسکرین، فونت‌ها، و فایل اکسل Switch Models همگی خودکار داخلش قرار می‌گیرن — با اضافه/تغییر فایل زیر `assets/` نیازی به فلگ اضافه نیست.

**اختیاری — همراه کردن `ssh.exe`:** یه نسخه از `ssh.exe` رو قبل از بیلد، توی ریشه‌ی پروژه (کنار `main.py`) بذار؛ همه‌ی اسکریپت‌های بیلد خودکار اون رو همراه برنامه بسته‌بندی می‌کنن. این‌جوری SSH حتی روی سیستمی که ویژگی OpenSSH Client ویندوزش فعال نیست هم بدون مشکل کار می‌کنه. اگه این کارو نکنی، برنامه فقط سراغ دستور `ssh` روی PATH سیستم می‌ره.

## ساخت یه فایل نصبی واقعی (Setup.exe)

برای یه تجربه‌ی واقعی دانلود-و-نصب (نصب توی Program Files، shortcut توی Start Menu، shortcut اختیاری روی دسکتاپ، و یه Uninstaller که توی "Add or remove programs" دیده می‌شه)، اول برنامه رو با یکی از اسکریپت‌های onedir بساز، بعد `build_installer.bat` رو اجرا کن. این اسکریپت از [Inno Setup](https://jrsoftware.org/isdl.php) (رایگان — یه‌بار نصبش کن) استفاده می‌کنه تا `dist\CiscoToolbox\` رو به یه فایل تکی `installer_output\CiscoToolboxSetup.exe` تبدیل کنه — همون یه فایل رو برای دانلود مردم آپلود کن.

## تست کردن

هر تب دستورها طوری ساخته شده که با سینتکس واقعی Cisco IOS مطابقت داشته باشه، ولی لطفاً قبل از تکیه کردن بهش برای تغییرات production، اول روی یه دستگاه آزمایشی تستش کن — مثل هر ابزاری که با کانفیگ زنده‌ی شبکه سروکار داره، اشتباه کردن سریع اتفاق می‌افته.

یه مجموعه تست خودکار کوچیک، منطق‌های بدون وابستگی به Qt رو که بقیه‌ی برنامه روشون ساخته شده، پوشش می‌ده: اعتبارسنجی ورودی‌ها (`core/validators.py`)، پاک‌سازی/مقایسه‌ی متن کانفیگ (`core/config_utils.py`)، و اصول رمزنگاری Black Box (`core/blackbox_crypto.py`).

```bat
pip install -r requirements-dev.txt
pytest
```

## یه نکته درباره‌ی ایمنی

این برنامه دستورهای واقعی رو روی دستگاه‌های واقعی و از طریق یه session زنده و واقعی می‌فرسته. چند تا چیز هست که برنامه برای امن‌تر کردن این کار انجام می‌ده:

- فیلدهای ورودی برای IP، آدرس MAC، شماره‌ی اینترفیس، و هاست‌نیم قبل از فرستادن هر چیزی، اعتبارسنجی می‌شن.
- WRITE MEMORY، COPY RUNNING-CONFIG STARTUP-CONFIG، Import Config، و Restore Backup همگی درست قبل از تماس با دستگاه، یه snapshot ایمنی خودکار از کانفیگ running می‌گیرن.
- عملیات‌های مخرب (Factory Reset) پشت یه هشدار صریح قرار دارن.

هیچ‌کدوم از این‌ها جایگزین تست کردن اول روی یه دستگاه آزمایشی و دونستن اینکه یه دستور چه کاری انجام می‌ده، قبل از زدن Apply نیست.

## مشارکت در پروژه

باگی پیدا کردی یا ایده‌ای برای یه قابلیت جدید داری؟ خوشحال می‌شم مشارکت کنی:

1. یه Issue باز کن و باگ یا درخواست قابلیتت رو توضیح بده.
2. برای تغییرات کد: ریپازیتوری رو fork کن، تغییرت رو اعمال کن، مجموعه تست رو اجرا کن (`pytest`)، و یه Pull Request باز کن.
3. منطق‌های جدیدی که نیازی به Qt ندارن (اعتبارسنجی، پارس کردن، رمزنگاری و...) رو توی `core/` نگه دار، تا تست واحدشون راحت بمونه — الگوی موجود توی `tests/` رو ببین.
4. اگه یه تب جدید اضافه کردی، اون رو با `_add_tab(...)` توی `ui/main_window.py` ثبت کن و یه ورودی دوزبانه هم بهش توی دیکشنری `TAB_HELP` اضافه کن، تا هم tooltip ❓ داخل برنامه و هم [جدول تب‌های](#مرور-سریع-تب‌ها) همین README به‌روز و دقیق بمونن.
